# Toolchains, build partition, and offline registries

Date: 2026-08-15. Status: approved (operator), build now, deploy at the next
incarnation boundary (do not restart the live agent container to apply this).

## Goal

Give the agent compiled-language toolchains (Rust, Common Lisp, plus smaller
paradigm languages), a disk-backed build area that cannot affect the host disk,
and the offline package ecosystems that make those toolchains whole. Add
record/text-manipulation tooling (filigree, loomweave, recutils, miller,
datamash) and a small read-only corpus volume. Add a diode `clone` command
delivering public GitHub repositories as inert tarballs.

## 1. Toolchains (agent image, apt)

`rustc` (1.85), `cargo`, `sbcl` (2.5.2), `gcc`, `libc6-dev`, `make`,
`pforth`, `swi-prolog-core`, `nasm`, `jq`, `sqlite3`, `libsqlite3-dev`,
`libffi-dev`, `miller`, `datamash` (recutils and gforth left trixie; pforth
substitutes for the forth paradigm and miller+datamash+sqlite3 cover
record manipulation).

Measured: core toolchain set (rustc+cargo+sbcl+gcc+libc6-dev) adds 688 MiB
installed. Verified: `cargo build` (std-only) and `sbcl --script` both work
under `--network none`. Final built image: 2.19 GB (from 843 MB) — the
toolchains plus swi-prolog, z3, and the filigree/loomweave wheels. This spec
is the design decision and the measurement CLAUDE.md requires. Note:
loomweave installs as a CLI binary only (Rust core, no importable Python
module); filigree is importable and provides a CLI.

No rustup, no Quicklisp client: every ecosystem arrives frozen and
offline-complete. Debian docs trees for the paradigm languages are excluded
(`--no-install-recommends`; no `-doc` packages) to keep tutorial-voiced
material out of the agent image (invariant 2).

## 2. /build partition

- A preallocated 5 GiB ext4 image file on the host:
  `fallocate -l 5G` (never sparse), `mkfs.ext4 -E root_owner=1000:1000 -m 0`.
  Created and loop-mounted at `volumes/build` by
  `scripts/create_build_volume.sh` (one `sudo mount`; an fstab line makes it
  survive reboots); compose bind-mounts `${AURORA_BUILD_DIR:-./volumes/build}`
  read-write at `/build` in the agent service only. Docker's local volume
  driver was found unable to loop-mount an image directly (`o: loop` is
  passed verbatim to the mount syscall and rejected), hence host-side mount
  plus bind. If the image is not mounted the bind silently degrades to a
  plain directory with no size boundary; the entrypoint detects this (same
  st_dev as /vendor) and prints a warning to the container log.
- Overflow guarantee: the host footprint is a fixed, preallocated 5 GiB
  whether the volume is empty or full. A full `/build` surfaces to the agent
  as ENOSPC and cannot consume main-disk space.
- Cleaning: `entrypoint.sh` empties `/build` at container start; the watchdog
  empties it in the `archive_reset` action (exit 42 and non-flapping exit 43),
  the same boundary where the transcript is archived and the tree reset.
  Exit-0 restarts resume a session and do not wipe. Tier-1/tier-2 recovery
  does not wipe (parallel to keeping gitignored notes). Watchdog self-reload
  does not re-run the entrypoint and therefore does not wipe mid-incarnation.
- Stated invariants: `/build` is mounted only into the agent, never the
  stage; it is excluded from the telemetry mirror (`mirror_work` copies only
  the working tree) and from tombstone archiving. Nothing outside the agent
  container reads it.
- Image env routes caches and artifacts onto it (the runtime home directory
  is read-only): `CARGO_HOME=/build/.cargo`, `CARGO_TARGET_DIR=/build/target`,
  `XDG_CACHE_HOME=/build/.cache`.

## 3. Offline registries (`/vendor`, read-only bind mount)

Closing guarantee for the volume: written only by the operator on the host at
provisioning time, mounted read-only into the agent alone, never into the
stage, carries no credential, and no harness component scans, imports, or
executes its contents.

### Rust: local registry

Plain `cargo vendor` cannot serve new projects (no index; verified failure).
The working mechanism (verified end-to-end under `--network none`, including
proc-macro crates, with no `--offline` flag needed):

1. A kitchen-sink manifest (`vendor/kitchen/Cargo.toml`, committed) lists the
   curated crates. Its lockfile is generated by the agent-side cargo (1.85)
   so the MSRV-aware resolver picks versions the agent's compiler can build.
2. `scripts/build_vendor.sh` runs `cargo local-registry --sync` (installed
   with `--locked` inside a throwaway `rust:latest` container; the tool needs
   a newer rustc than trixie ships, the produced registry does not) writing
   index + `.crate` files to `volumes/vendor/registry`.
3. The image bakes `/.cargo/config.toml` replacing `crates-io` with
   `local-registry = "/vendor/registry"`.

Curated seed set (plus transitive deps, versions frozen by the lockfile):
- languages and parsing: nom, pest, pest_derive, logos, chumsky, lalrpop
- foundations: serde, serde_json, anyhow, thiserror, itertools, rand,
  regex, indexmap, num, num-bigint, smallvec, bitvec
- concurrency: rayon, crossbeam, parking_lot, flume
- async and sockets: tokio, hyper, hyperlocal, http, bytes, futures
- embedding and substrates: mlua (vendored lua), wasmi, pyo3, cc, libc
- storage and wire formats: sled, bincode, rmp-serde, sha2, hex, base64,
  flate2, tar
- testing and interfaces: proptest, criterion, clap, rustyline

### Common Lisp: Quicklisp bundle

`ql:bundle-systems` output (self-contained, loads through bundled ASDF, no
client, no network) built by `scripts/build_vendor.sh` in a container, into
`volumes/vendor/lisp`. Systems: alexandria, serapeum, bordeaux-threads,
lparallel, cl-ppcre, iterate, esrap, trivia, closer-mop, usocket, yason,
jsown, fset, local-time, str, fiveam, cffi, hunchentoot, slynk, cl-sqlite.

### Static embeddings (`/vendor/models`)

A Model2Vec static sentence-embedding model (potion-base-8M, ~30 MB:
model.safetensors, tokenizer.json, config.json) fetched by
`scripts/build_vendor.sh`. Inference is numpy-only through the `model2vec`
package (deps: numpy, safetensors, tokenizers — no torch, no onnxruntime),
so this stays outside the ML-runtime class CLAUDE.md restricts; this section
is the required design decision and measurement. It gives the agent a bulk
semantic-similarity faculty for organizing its own artifacts. Verified
loading and embedding offline from the local directory. A hosted
high-quality embedder as a gated diode command remains a possible future
channel spec; it composes with, and does not replace, this local faculty.

### Python additions (`requirements-agent.txt`)

z3-solver, tenacity, hy, jplephem, model2vec, filigree, loomweave. filigree and loomweave install
from wheels built out of the operator's local source trees (`~/filigree`,
`~/loomweave`) by `scripts/build_local_wheels.sh` into `vendor/wheels/`
(gitignored); the Dockerfile installs the wheels before the requirements
file, so the manifest lines are already satisfied and PyPI is not consulted
for them. The manifest stays the single source of truth for the garden
inventory. Measured: filigree+loomweave and their new deps add ~105 MB of
site-packages.

## 5. Corpus (`/corpus`, read-only bind mount)

Same closing guarantee as `/vendor`. Fetched by `scripts/fetch_corpus.sh`
into `volumes/corpus/` (checksummed, resumable):
- chess: Syzygy 3-4-5 tablebases (~938 MB)
- sky: JPL DE440s ephemeris (~32 MB), HYG star catalog (~30 MB)
- sequences: OEIS `stripped` file only (~60 MB uncompressed); the `names`
  file and full oeisdata are excluded (reader-addressed prose)
- writing: Unicode UCD (~7 MB), a Noto font subset (ttf/otf files only, no
  designer READMEs)
Provider README files are dropped everywhere; data files only (invariant 2).

## 7. Diode `clone` command (separate commit, droppable)

`clone <owner>/<repo> [ref]`: owner, repo, ref validated against strict
identifier patterns; no URL or path crosses the diode. Implemented as an
HTTPS GET of `https://codeload.github.com/<owner>/<repo>/tar.gz/<ref>`
(default ref HEAD), host pinned, existing SSRF and redirect defenses apply,
response size capped (`CLONE_MAX_BYTES`, default 50 MB), spend counted
against the fetch budget. The result is written to `output/` as a single
inert `.tar.gz` artifact; the diode never extracts it. Public repositories
only; no token exists anywhere in the path. Listed in HELP.md.
